Data raport: 2026-07-15
Restrictii respectate: analiza binarului s-a facut prin MCP ghidra; nu s-au facut patch-uri, rename-uri sau comentarii in Ghidra.

- API-uri Windows: GetModuleHandleA, SetWindowsHookExA, GetLastError.

  - SetWindowsHookExA(0xd, &DAT_1400088d7, module, 0) -> camp param_1+0x78.
  - SetWindowsHookExA(0xe, &DAT_1400088d7, module, ...) -> camp param_1+0x80.
  - logheaza erori daca hook-urile esueaza.
- Concluzie: componenta captureaza evenimente globale de tastatura/mouse.
- Incredere: ridicata.

4. Flux probabil de captura

Fapte confirmate static:
1. FUN_14003ee60 instaleaza SetWinEventHook si hook-urile low-level.
2. FUN_14003e8e0 instaleaza WH_KEYBOARD_LL / WH_MOUSE_LL.
3. FUN_140040dd0 actualizeaza HWND-ul curent la obiect+0x90 pe evenimente focus.
4. FUN_1400405d0 colecteaza input, foloseste HWND curent/foreground, PID/thread/layout si ToUnicodeEx.
5. FUN_140047d80 obtine HWND foreground din desktopul activ.
6. FUN_1400471d0 obtine PID, titlu fereastra, path/nume proces si filtreaza ferestrele.
7. FUN_140046190 stocheaza metadata pe HWND intr-un QMap la obiect+0x68.
8. FUN_1400515a0 obtine rect/DC pentru HWND.
9. FUN_1400501d0 captureaza cu PrintWindow sau BitBlt si extrage pixeli cu GetDIBits.
10. IPC-ul local include named pipes si shared memory; Qt/SSL/socket indica transmitere mai departe.

Ipoteza:
- Fluxul complet este:
  schimbare focus / hook input -> HWND curent -> PID/titlu/path -> decizie fereastra/desktop -> captura GDI -> DIB/pixel buffer -> conversie/impachetare -> IPC shared memory/named pipe/local socket -> transport mai departe.

5. Structuri / variabile probabile

Fapte:
- Obiectul folosit de focus/input:
  - +0x78: handle WH_KEYBOARD_LL.
  - +0x80: handle WH_MOUSE_LL.
  - +0x88: handle SetWinEventHook.
  - +0x90: HWND curent/foreground salvat.
  - +0x98: flag folosit in tratarea ToUnicodeEx/dead keys.
- Obiectul metadata ferestre:
  - param_1+0x68 in FUN_140046190: QMap indexat dupa HWND.
  - nod QMap actualizat:
    +0x20 HWND
    +0x28 titlu/label
    +0x30 PID ca QString
    +0x38 process/path lower-case
    +0x40 extra string/app-id
    +0x48..+0x54 coordonate/dimensiuni.
- Captura GDI:
  - FUN_1400501d0 foloseste context+0x10+0x418 ca buffer de pixeli rezultat din GetDIBits.
  - context+0x18 pare contor/capacitate disponibila; context+0x20 seteaza dimensiune necesara daca bufferul este insuficient.

Ipoteze:
- "ultimul HWND" este campul obiect+0x90 si/sau cheia curenta in QMap param_1+0x68.
- "ultimul PID/titlu" sunt campurile QMap +0x30 / +0x28 asociate HWND-ului.
- "ultimul frame" nu este identificat ca QImage aici; in acest binar captura bruta este GDI/DIB in buffer intern, iar pipeline-ul QImage/delta vazut in tlshost.exe poate fi o etapa separata.

6. Relatia observata cu celelalte executabile

Fapte:
- Nu exista string-uri directe tlshost/tlsservice/tlssubservice/tssubservice in cautarile curente.
- Exista IPC named pipe compatibil structural cu cel observat in tlshost.exe.
- Exista shared memory agent channel aproape analog cu cel din tlshost.exe.
- Exista WTS/user-token/session helpers si CreateProcessAsUserW importat, dar nu am finalizat o functie de launch clara echivalenta cu cea din tlshost.exe.

Ipoteza:
- tlsservice.exe este componenta care ruleaza in context/sesiune interactiva sau are acces la desktopul interactic si face efectiv detectia focusului, colectarea inputului si captura GDI. tlshost.exe pare mai mult host/transport/video sequencer/orchestrare, iar tlsservice.exe contine codul mai direct pentru HWND/input/GDI.

7. Top 5 cauze posibile pentru captura blocata pe Chrome desi utilizatorul lucreaza in AutoCAD

Fapte relevante:
- HWND curent se salveaza la obiect+0x90.
- Metadata pe HWND se pastreaza in QMap la param_1+0x68.
- Captura foloseste PrintWindow pentru hwnd non-foreground si BitBlt pentru foreground/desktop DC.
- Desktop/input desktop sunt schimbate explicit prin OpenInputDesktop/SetThreadDesktop.

Ipoteze:
1. obiect+0x90 nu se actualizeaza la schimbarea focusului spre AutoCAD; cauza posibila: SetWinEventHook/callback blocat, message loop oprit sau desktop gresit.
2. FUN_140047d80 ramane pe desktop/window station vechi sau OpenInputDesktop/SetThreadDesktop esueaza; GetForegroundWindow returneaza in continuare HWND Chrome.
3. QMap-ul de metadata param_1+0x68 pastreaza intrarea Chrome si nu primeste/nu accepta AutoCAD din cauza filtrelor IsWindowVisible/GetWindowLongPtrW/GetWindowInfo.
4. Captura AutoCAD prin PrintWindow/BitBlt/GetDIBits esueaza sau returneaza negru/vechi din cauza randarii GPU; pipeline-ul pastreaza ultimul frame valid Chrome.
5. Dimensiunea/bufferul din FUN_1400501d0 este insuficient sau GetDIBits esueaza pentru AutoCAD; context+0x20 seteaza necesar nou, dar frame-ul transmis ramane cel anterior.

9. Concluzie finala

Rol probabil al tlsservice.exe:
- Foarte probabil componenta Kickidler/TLS care detecteaza fereastra activa, colecteaza activitate input si captureaza ecran/fereastra in sesiunea interactiva a utilizatorului.
- Spre deosebire de tlshost.exe, aici exista dovezi directe pentru hook-uri Windows, HWND/PID/titlu, desktop switching si captura GDI.

Functii principale:
- Focus/input: FUN_14003ee60, FUN_14003e8e0, FUN_140040dd0, FUN_1400405d0, FUN_140047d80.
- Metadata ferestre: FUN_1400478b0, FUN_1400471d0, FUN_140046190.
- Captura: FUN_1400515a0, FUN_1400501d0.
- IPC: FUN_14016ace0, FUN_1400c37f0, FUN_1400c38d0, FUN_1400c3960, FUN_1400c3af0.

Nivel general de incredere:
- Ridicat ca tlsservice.exe este componenta care face detectia ferestrei active si colectarea activitatii.
- Foarte ridicat ca are captura GDI prin PrintWindow/BitBlt/GetDIBits.
- Mediu ca transmite frame-urile direct; transportul complet nu a fost reconstruit integral in aceasta trecere, dar IPC-ul local este confirmat.
