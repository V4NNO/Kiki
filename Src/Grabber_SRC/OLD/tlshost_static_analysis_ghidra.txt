4. Flux probabil de captura

Fapte observate:
- Exista pipeline video explicit in app/impl-grabber-video.
- Frame-urile sunt QImage, asteptate in format RGB555.
- FUN_14028ee20 pastreaza/compara frame anterior si frame curent si emite full frame sau rect-uri delta.
- FUN_14028fcd0 serializeaza rect/frame in QByteArray.
- FUN_14028c570 trimite frame-ul catre logica de sesiune/transport.
- IPC local include named pipe, anonymous pipe, shared memory si mutex.
- FUN_140086b60 lanseaza procese in sesiunea utilizatorului prin WTS/CreateProcessAsUserW.

Ipoteza separata de fapte:
- fluxul probabil este:
  agent/session in user session produce QImage -> video stream sequencer tine ring buffer/ultimul frame -> video sink decide stream/fps -> frame/delta se serializeaza -> transport/session -> IPC/retea catre serviciu/backend.
- Nu am confirmat static in aceasta trecere rutina concreta care detecteaza HWND/focus sau produce initial QImage din desktop/window. API-urile clasice GetForegroundWindow/BitBlt/PrintWindow nu apar ca import direct/string.

5. Variabile / structuri probabile

Fapte:
- In structura folosita de FUN_14028e700/FUN_14028ee20:
  - +0x18: dimensiune/capacitate buffer frame.
  - +0x20: container/ring buffer.
  - +0x28: index ring buffer citire.
  - +0x2c: count frame-uri disponibile.
  - +0x30: flag care opreste returnarea frame-urilor.
  - +0x38/+0x40: timestamp si QImage asociate ultimului frame procesat/trimis.
  - +0x60/+0x68: timestamp si QImage resetate de FUN_14028f800; par a fi ultim frame de comparatie sau stare cache.
- In FUN_1402a3ab0 shared memory:
  - offset 0: counter global DAT_140540824.
  - offset 8: QCoreApplication::applicationPid().

Ipoteze:
- "ultimul frame" este foarte probabil unul dintre QImage-urile la +0x40 sau +0x68.
- "starea thread-ului de captura" nu este confirmata; exista QTimer si QThread in importuri, iar FUN_14028db10 ajusteaza timerul de fetch.
- Nu au fost identificate structuri pentru ultim HWND/ultim PID/ultim titlu fereastra in aceasta trecere. Lipsa importurilor window API reduce increderea ca tlshost.exe face direct tracking HWND.

6. Relatia observata cu celelalte executabile

Fapte:
- FUN_140089540 mapeaza familia TLS: tlshost / tlsservice / tlssubservice / tls / "Telemetry Service Host".
- String-uri pentru tlsservice.exe si tlssubservice.exe exista si sunt referite din aceeasi functie.
- FUN_140086b60 poate lansa procese in sesiuni de user cu CreateProcessAsUserW, folosind nume/path construite din QCoreApplication::applicationFilePath/applicationDirPath si maparea numelor.

Ipoteza:
- tlshost.exe este probabil host/agent de telemetry/grabber care poate rula in sesiunea utilizatorului, iar tlsservice/tlssubservice sunt componente de serviciu/subserviciu pentru control/orchestrare.

7. Top 5 cauze posibile pentru captura blocata pe Chrome desi utilizatorul lucreaza in AutoCAD

Fapte care sustin analiza:
- Pipeline-ul video pastreaza frame anterior si face delta/full frame in FUN_14028ee20.
- Exista flag de pauza la +0x30 si reset de frame cache in FUN_14028f800.
- Timerul de fetch este ajustat in FUN_14028db10 si poate fi oprit daca rata devine 0.
- Nu a fost confirmata detectia activa HWND/PID in tlshost.exe prin API-urile cerute.

Ipoteze:
1. Producatorul de QImage nu mai introduce frame-uri noi in ring buffer (+0x2c ramane 0), iar ultimul frame valid ramane Chrome.
2. Flagul de pauza/dezactivare (+0x30) ramane setat pentru streamul curent; FUN_14028ee20 returneaza null si nu actualizeaza frame-ul.
3. Detectia focus/HWND este in alt proces/modul si nu transmite schimbarea Chrome -> AutoCAD catre tlshost; tlshost continua streamul anterior.
4. AutoCAD este capturat prin GPU/DirectX/OpenGL si mecanismul real de captura esueaza, dar cache-ul/delta encoderul pastreaza ultimul QImage valid.
5. Timerul/fetch forcer din FUN_14028db10 se opreste sau intervalul devine gresit, deci captura nu mai este solicitata desi sesiunea continua.

9. Concluzie finala

Rol probabil al tlshost.exe:
- Componenta Kickidler/Tele Link Soft Helper cu rol de host/agent pentru telemetry/grabber, transport si/sau orchestrare in sesiunea utilizatorului. Are cod explicit de grabber video, agent channel, sesiuni WTS si relatii cu tlsservice/tlssubservice.

Functii principale identificate:
- FUN_140086b60: lansare/gestionare proces in sesiune user prin WTS + pipe.
- FUN_140089540: mapare nume familie executabile TLS/grabber.
- FUN_1402a3ab0: agent channel prin mutex + shared memory.
- FUN_14018ad90/FUN_14018af00/FUN_14018b090: named pipe IPC.
- FUN_14028b2c0/FUN_14028c570/FUN_14028e700/FUN_14028ee20/FUN_14028fcd0: pipeline video QImage, delta/full frame, serializare.
- FUN_140127170: OpenGL telemetry/capability test.

Nivel general de incredere:
- Ridicat ca tlshost.exe este componenta Kickidler/TLS cu functie de grabber/telemetry si IPC.
- Ridicat ca exista pipeline intern de frame video QImage.
- Mediu-scazut ca tlshost.exe insusi detecteaza direct HWND/PID/fereastra activa, deoarece API-urile clasice cerute nu apar importate direct sau ca string-uri in analiza curenta.
