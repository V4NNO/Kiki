8. Top 5 cauze posibile pentru captura blocata pe Chrome desi userul lucreaza in AutoCAD
===============================================================================

IMPORTANT:
- Cauzele de mai jos sunt ipoteze pentru sistemul global Kickidler, nu dovezi directe din tssubservice.exe. In tssubservice.exe nu am observat codul care pastreaza ultimul HWND/frame.

1. Stare "last active HWND/PID" blocata in tlsservice.exe
   - Fapt suport: tlsservice.exe, nu tssubservice.exe, contine GetForegroundWindow/GetGUIThreadInfo/WinEvent hooks.
   - Ipoteza: handler-ul de focus nu actualizeaza HWND cand AutoCAD devine activ sau callback-ul WinEvent se blocheaza.
   - Test: breakpoint in tlsservice.exe la GetForegroundWindow/GetGUIThreadInfo/SetWinEventHook callback si compara HWND/PID Chrome vs AutoCAD.

2. Captura PrintWindow/BitBlt esueaza pentru AutoCAD si pipeline-ul reutilizeaza ultimul frame valid
   - Fapt suport: tlsservice.exe contine PrintWindow/BitBlt/GetDIBits; tssubservice.exe nu.
   - Ipoteza: AutoCAD foloseste suprafete accelerate/GPU care nu raspund bine la PrintWindow/BitBlt, iar codul trimite ultimul frame Chrome.
   - Test: breakpoint in tlsservice.exe la PrintWindow/BitBlt/GetDIBits si verifica return code cand AutoCAD este activ.

3. Thread-ul/event loop de captura este blocat sau asteapta un semnal vechi
   - Fapt suport: tlsservice.exe are thread-uri/WaitCondition pentru captura; tssubservice.exe are event loop Qt si IPC.
   - Ipoteza: pipeline-ul captureaza in thread separat si ramane pe bufferul anterior.
   - Test: debugger pe thread-urile tlsservice.exe; inspecteaza waits, critical sections si timestamp-ul ultimului frame.

4. Canal IPC/transport mentine un state vechi sau pierde mesajul de schimbare focus
   - Fapt suport: tssubservice.exe foloseste named pipe/localRPC; tlshost/tlsservice au IPC similar.
   - Ipoteza: evenimentul de schimbare focus se pierde intre componenta de detectie si componenta de transport, iar UI/transport continua sa trimita metadata/frame vechi.
   - Test: breakpoint/log pe TransactNamedPipe/WriteFile in toate procesele si corelare timestamp focus/frame.

5. Problema de desktop/session/integrity/privilegii pentru AutoCAD
   - Fapt suport: tlsservice.exe foloseste OpenInputDesktop/SetThreadDesktop in analiza anterioara; tssubservice.exe porneste pe session id curent.
   - Ipoteza: AutoCAD ruleaza elevat, pe alt desktop, sau cu grafica/privilegii care blocheaza capturarea, iar serviciul ramane cu captura Chrome.
   - Test: compara integrity level si session/desktop pentru Chrome, AutoCAD, tlsservice.exe, tssubservice.exe; testeaza AutoCAD normal vs elevated.
