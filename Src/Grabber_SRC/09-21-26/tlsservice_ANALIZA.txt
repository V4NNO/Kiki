4. ARHITECTURA SI FLUXUL DATELOR

Fluxul principal observat este:

  Desktop/sesiune utilizator
       -> colectoare (display, input, programe, ecran, audio, web)
       -> grabberAgent::Communicator
       -> canal IPC / subAgentIo::Bridge
       -> serviciul gazda si protocoalele Grabber

Communicator-ul coordoneaza activarea colectoarelor si trimite obiecte Qt si
mesaje de protocol. Bridge-ul porneste grabberSubAgent cu "-ipc-name" si
"-logging-postfix", monitorizeaza PID-ul si gestioneaza reconectarea/oprirea.

8. CAPTURA DE ECRAN

Componente:

- implementare GDI;

Fluxul prefera captura DXGI. Comportamentul observat direct include:

- normalizarea imaginilor si verificarea bpp/stride.

Ruta GDI foloseste DC-uri compatibile si PrintWindow/BitBlt pentru cazurile in

- transmite "-ipc-name" si postfixul de logging;
- porneste procesul si retine PID-ul;
- gestioneaza canalul IPC, erorile, restartul si shutdown-ul.

12. AUDIO

Componente:
- grabberAgent::AudioEnumerator;
- details::AudioEnumeratorImpl;
- PortAudio 19.7;
- backend WASAPI si COM audio-session APIs;
- notificari IAudioSessionNotification / IAudioSessionEvents.

AudioEnumerator descopera endpoint-urile si sesiunile audio, deschide stream-uri
PortAudio si produce cadre pentru communicator. Implementarea foloseste un
thread de update si o coada de task-uri pentru:
- actualizarea device-urilor;
- actualizarea sesiunilor;
- begin/end record;
- oprire controlata.

Versiunea analizata contine optiunea "recordOnlyWhenCaptureActive". Cand este
activa, gate-ul de inregistrare:
- se deschide la detectarea unei sesiuni care captureaza audio;
- poate urmari alte sesiuni fara a emite cadre cat timp gate-ul este inchis;
- se inchide cand nu mai exista sesiuni de capturare;
- curata sesiunile disparute si trateaza stream-urile care nu se pot deschide.

AUDIODG.EXE este tratat explicit, iar erorile de initializare, device si stream
sunt raportate cu motivul furnizat de PortAudio/WASAPI.

15. CONCLUZIE

tlsservice.exe este agentul interactiv al Grabber-ului. El ruleaza in sesiunea
utilizatorului si colecteaza topologia display-urilor, activitatea/input-ul,
programele, ferestrele, starea sesiunii, continutul vizual, informatia web si
sesiunile audio. Datele sunt agregate de Communicator si transferate prin
subAgentIo/IPC catre restul infrastructurii. Captura video foloseste DXGI cu
fallback GDI, iar audio foloseste PortAudio/WASAPI cu un gate dependent de
existenta unei sesiuni de capturare.
