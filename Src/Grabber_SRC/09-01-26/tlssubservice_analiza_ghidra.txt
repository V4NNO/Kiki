ANALIZA STATICA GHIDRA MCP - tlssubservice.exe / grabberSubAgent
Data: 2026-09-01

1. IDENTIFICAREA PROGRAMULUI ANALIZAT

Analiza a fost efectuata asupra programului activ din Ghidra MCP, deschis de
utilizator ca tlssubservice.exe.

Observatie importanta: binarul activ nu contine literalul "tlssubservice.exe"
sau "tlssubservice". Identitatea interna si rolul sunt sustinute de:

- 0x1400DBE50:
  R:\bbuild-8\KICK-EVPROD-WIN64\components\app-grabberSubAgent\main.cpp
- 0x1400DBEE0: "KickidlerGrabber"
- 0x1400DBF40: "-ipc-name"
- 0x1400DDD50: "grabberSubAgent::io::Service"
- cai de build impl-grabberSubAgent-io, -userInfo, -http si -ui.

Concluzia prudenta este ca programul analizat este componenta
grabberSubAgent folosita sub numele extern tlssubservice.exe. Maparea numelui
tlssubservice apare in tlshost.exe, nu ca literal in acest subagent.

Fisierul tlssubservice.exe nu este prezent ca fisier normal in arborele local
al workspace-ului. Nu au putut fi calculate local hash-ul, dimensiunea sau
semnatura Authenticode; analiza foloseste programul incarcat in Ghidra.

2. FORMAT, LIMBAJ SI TOOLCHAIN

- Executabil PE pe 64 de biti, image base 0x140000000.
- Limbaj principal: C++.
- Runtime/compiler: Microsoft Visual C++ din generatia v14, indicat de CRT,
  __security_init_cookie, RTTI si template-urile C++.
- Framework: Qt 5.6.2, vizibil in caile de build si in importurile/clasele
  QApplication, QLocalServer, QLocalSocket, QNetworkAccessManager, QJsonDocument,
  QClipboard, QSystemTrayIcon, QImage si QML/Quick.

Concluzie: extensia .cpp este corecta. Fisierul
tlssubservice_ghidra_decompiled.cpp contine pseudocodul C/C++ emis de Ghidra,
cu numele FUN_/DAT_/LAB_ pastrate si fara functii inventate.

4. PORNIREA SI MODURILE APLICATIEI

- entry @ 0x140002F3B initializeaza security cookie-ul si transfera controlul
  catre startup-ul CRT FUN_1400B8390.
- FUN_140017280 @ 0x140017280 are semnatura
  int FUN_140017280(int param_1, char **param_2) si este functia main.
- Numele aplicatiei Qt este "KickidlerGrabber".
- Este construita QApplication si este dezactivata inchiderea automata la
  disparitia ultimei ferestre prin QGuiApplication::setQuitOnLastWindowClosed.
- Codul proceseaza optiunile "-get-network-proxies", "-logging-postfix" si
  "-ipc-name".
- Sunt apelate SetProcessShutdownParameters, GetCurrentProcessId si
  ProcessIdToSessionId, iar identificatorul sesiunii este inclus in eticheta
  subagentului.
- In modul IPC este creat serviciul local, este pornit listener-ul si apoi
  aplicatia intra in QApplication::exec().

5. MODUL AUXILIAR -get-network-proxies

Daca primul argument este "-get-network-proxies", main apeleaza
FUN_1400148A0 @ 0x1400148A0.

Aceasta functie:

- interogheaza QNetworkProxyFactory::systemProxyForQuery;
- parcurge lista de QNetworkProxy;
- extrage pentru fiecare intrare type, hostName, password, port si user;
- construieste structuri QVariant/QMap;
- serializeaza rezultatul prin QJsonDocument::fromVariant si toJson.

Acesta corespunde helper-ului lansat de tlshost.exe in sesiunea utilizatorului.
In analiza tlshost, procesul copil era pornit cu CreateProcessAsUserW, iar
rezultatul JSON era citit din pipe si interpretat prin campurile "uid" si
"proxies".

6. PARAMETRUL OBLIGATORIU -ipc-name

In modul normal, main cauta argumentul "-ipc-name". Daca nu exista:

- logheaza "IPC name not specified";
- nu porneste serviciul local normal.

Daca numele IPC este prezent:

- construieste grabberSubAgent::io::Service;
- transmite numele catre FUN_14001C2C0;
- intra in event loop-ul QApplication.

Numele pipe/socket-ului nu este fix in binar; este primit la runtime. Aceasta
explica de ce legatura cu tlshost/tlsservice nu necesita un literal cu numele
executabilului in subagent.

14. RETEA SI SSL

Programul foloseste QNetworkAccessManager si include tipuri/importuri pentru
QSslCertificate, QSslConfiguration, QSslKey si semnalul encrypted. Aceasta
permite cereri HTTPS in subsistemul HTTP. In functiile selectate, logica
principala este la nivel QNetworkAccessManager, nu implementarea directa a
handshake-ului TLS.

15. DIFERENTA FATA DE tlsservice.exe SI tlshost.exe

In importurile tlssubservice/grabberSubAgent nu apar:

- GetForegroundWindow, GetGUIThreadInfo, SetWinEventHook sau SetWindowsHookEx;
- OpenInputDesktop sau SetThreadDesktop;
- PrintWindow, BitBlt sau GetDIBits;
- WTSEnumerateSessionsW, WTSQueryUserToken sau CreateProcessAsUserW;
- OpenSCManagerW sau CreateServiceW.

Separarea sustinuta de cele trei analize:

- tlsservice.exe: focus/input, desktop interactiv si captura GDI;
- tlshost.exe: serviciu Windows, sesiuni WTS, pornirea proceselor utilizator,
  manageri/collector, transport si rutarea cadrelor video;
- tlssubservice.exe/grabberSubAgent: IPC local, proxy-uri sistem, informatii
  utilizator/AD, clipboard, HTTP si interfata self-control/notificari.

16. CONCLUZIE

Programul activ este o aplicatie C++ x64, compilata cu Microsoft Visual C++ si
bazata pe Qt 5.6.2. Continutul confirma rolul grabberSubAgent folosit ca
tlssubservice: un proces auxiliar din sesiunea utilizatorului, controlat prin
QLocalServer/QLocalSocket si RPC.

Capabilitatile confirmate static sunt:

- modul JSON pentru enumerarea proxy-urilor sistemului;
- server IPC cu nume primit prin -ipc-name;
- operatii RPC pentru user info, proxy, clipboard si UI;
- interogare Active Directory/LDAP/registry;
- citire si modificare clipboard, inclusiv imagini PNG si MIME;
- cereri HTTP GET/POST cu JSON si web token;
- tray icon, notificari, branding, self-control si task tracker;
- integrare Qt Quick/QML.

Analiza este statica. Ea confirma codul si traseele disponibile, dar nu poate
demonstra singura ce comenzi sunt trimise intr-o instalare concreta sau ce
date sunt efectiv schimbate la runtime.
