3. PORNIREA APLICATIEI

- entry @ 0x140024A8C initializeaza security cookie-ul.
- Startup-ul CRT este FUN_1404D5F00.
- FUN_140108C30(int, ...) este functia main, identificata prin
  "KickidlerViewer" si main.cpp.
- Aplicatia seteaza numele Qt, initializeaza caile si logging-ul si instaleaza
  un Qt message handler.
- Este construita aplicatia principala si apoi este pornit QApplication::exec().

Moduri speciale observate:
- "-utilize-invite": flux separat pentru utilizarea unei invitatii;
- "-encrypt <valoare>": transforma valoarea si o scrie la stdout;
- "report ...": porneste modul de raportare/telemetrie;
- modul normal: initializeaza Viewer-ul complet.

4. VALIDARI LA INITIALIZARE

Rezultatul initializarii aplicatiei este tratat explicit:
- succes;
- aplicatie deja pornita;
- initializare esuata;
- sistem fara suport OpenGL;
- versiune OpenGL mai mica de 2.1.

Viewer-ul foloseste mecanism de single-instance bazat pe QtSingleApplication,
fisier blocat si local peer. Pentru erori sunt afisate QMessageBox-uri cu
mesaje clare. OpenGL este necesar pentru randarea anumitor componente video/UI.

5. ARHITECTURA GENERALA

Fluxul principal este:

  servere/node-uri
       -> transport SSL si protocoale tipate
       -> loader-e pe functionalitati
       -> modele/engines Viewer
       -> obiecte Qt/QML si ferestre
       -> utilizator

Subsistemele folosesc conexiuni Qt signal/slot si modele expuse in QML.
Conexiunile catre node sunt separate pe rute precum control4Viewer,
historyVideo4Viewer, historyAudio4Viewer, keylogger4Viewer si
violations4Viewer.

6. MONITORIZAREA ONLINE

Modelele principale sunt:
- viewer::online::Client;
- Node;
- Grabber;
- Session;
- Monitor;
- engine::Info / InfoLoader;
- engine::Video / VideoLoader.

Ierarhia este Node -> Grabber -> Session -> Monitor. Clientul mentine listele
de noduri si grabber-e online. InfoLoader primeste starea sesiunilor,
display-urile, programele, input idle, lock/saver si alte metadate.

VideoLoader:
- urmareste monitoarele solicitate;
- primeste cadre complete si cadre delta;
- pastreaza ultima imagine valida;
- aplica subcadrele delta peste cadrul anterior;
- ignora delta-urile invalide pana la urmatorul cadru complet;
- emite actualizari catre obiectele Monitor/QML.

Mesajele "invalid delta subframe image, skip until next full frame" si
"invalid delta frame vectors" confirma mecanismul de recuperare dupa pierderea
sau coruperea lantului delta.

7. ISTORIC VIDEO

Componente:
- VideoStore;
- Gauge;
- Block;
- CacheIndex / CacheData;
- InfoSelector;
- VideoComposer;
- VideoSaver;
- engine::Loader.

VideoStore descarca segmentele solicitate de la nod si le salveaza intr-un
cache SQLite. Pentru reconstruirea imaginii:
- cauta un cadru suport/complet;
- valideaza cadrul complet;
- aplica succesiv vectorii de subcadre delta;
- detecteaza statusuri, dimensiuni si imagini invalide;
- corecteaza segmentele cache-ului.

Gauge si Block reprezinta intervalele disponibile si bucatile incarcate.
VideoComposer sincronizeaza imaginea cu informatia de sesiune, iar VideoSaver
exporta secventa video, gestionand cadrele si progresul salvarii.

8. ISTORIC AUDIO

Componente:
- AudioStore;
- AudioStoreDb;
- AudioPlayer.

AudioStore solicita descrierile stream-urilor si cadrele audio pentru
intervalele dorite. Datele sunt corelate prin node ID, online session ID,
device si timestamp.

AudioStoreDb:
- pastreaza segmentele intr-o baza SQLite;
- stocheaza descrierile stream-urilor;
- actualizeaza inceputul/sfarsitul segmentelor;
- scrie payload-ul audio in fisiere;
- verifica tipul codecului si erorile de I/O.

AudioPlayer reda fluxul sincronizat cu pozitia playerului si se poate opri
automat din cauza inactivitatii. Sunt separate dispozitivele de inregistrare
si playback si exista suport pentru mute si intervalele audio disponibile.

9. CONTROL REMOTE

Componente:
- viewer::control::Master;
- viewer::control::Channel;
- viewer::control::utils::FilesTransporter;
- PasteUrlsHandler.

Master:
- porneste conexiunea catre nod;
- solicita punctul slave;
- poate porni un client sau un server de control;
- urmareste deschiderea/inchiderea conexiunii;
- proceseaza starea si ripeness-ul slave-ului.

Channel:
- executa autorizarea;
- respinge autentificarea invalida;
- transmite comenzile mouse/tastatura;
- sincronizeaza display-ul si cursorul;
- transmite clipboard text, HTML, imagine si fisiere.

Transferul de fisiere foloseste mesaje FsPrepareReceive, FsData, FsEcho,
FsConflictSolution si FsConflictContent. FilesTransporter gestioneaza lista,
progresul, conflictele si destinatia transferurilor. PasteUrlsHandler
integreaza copierea/lipirea fisierelor cu Windows.

10. KEYLOGGER

Componente:
- viewer::keylogger::Selector;
- Chart / Result / Translator;
- engine::Provider / Dataset / Loader.

Selector-ul defineste intervalul, sesiunile si filtrele. Loader-ul deschide
ruta keylogger4Viewer, trimite SelectKeyboardEvents si primeste
KeyboardEvents. Provider-ul transforma evenimentele brute intr-un dataset,
coreland tastele cu aplicatia si timpul. Rezultatele sunt expuse modelelor
QML si pot fi exportate.

Functionalitatea este conditionata de setarile v2o/dc pentru
"isKeyloggerEnabled".

11. ORGANIZATIE

Subsistemul organization gestioneaza:
- departamente;
- angajati;
- grabber-e;
- relatii one-to-many;
- session markers;
- filtre pentru afisarea angajatilor online.

Indexurile si engine-urile mentin corespondenta intre structura organizatiei
si sesiunile/grabber-ele primite de la server. Aceasta structura este folosita
de ecranele Online, History, Charts si Violations.

12. VIOLATIONS

Componente:
- viewer::violations::engine::Manager;
- Loader;
- SubscribersContainer;
- Group / Filter / Event;
- FiltersContainer.

Loader-ul foloseste ruta violations4Viewer si primeste rezultate de calcul
pentru filtre. Manager-ul coreleaza selectoarele, grupurile si abonatii.
Protocolul permite:
- cereri de calcul pentru filtre;
- abonare la rezultatele filtrelor;
- sincronizarea configuratiei violations;
- afisarea evenimentelor si grupurilor in UI.

Conexiunile deschise si inchise sunt logate per node.

13. APLICATII, CHARTS SI RAPOARTE

Binarul include:
- viewer-applications pentru indexarea si afisarea aplicatiilor;
- viewer-charts pentru selectoare, loader-e si serii de date;
- exportToCsv;
- exportToXlsx prin biblioteca QtXlsx.

QtXlsx gestioneaza workbook-uri, worksheet-uri, stiluri, stringuri partajate,
validari, desene si chart-uri. Acest subsistem permite exportul rapoartelor si
dataset-urilor produse de Viewer.

14. FERESTRE SI UI

viewer::windows::Manager coordoneaza ferestrele aplicatiei, iar Window,
KeyboardGrabber si Timer gestioneaza focusul, capturarea tastelor la nivelul
ferestrei si temporizatoarele UI.

GUI-ul foloseste QML/Quick, configurare dinamica si screen/directory informer.
Modelele Viewer sunt inregistrate ca tipuri sau proprietati QML, iar
configEngine si dataProcessor distribuie setarile intre componente.

15. RETEA, BILLING SI SECURITATE

Transportul foloseste:
- QSslSocket si configurari SSL;
- certificate si chei;
- peer verification;
- canale separate per protocol;
- reconectare si buffering.

Billing-ul verifica identitatea Viewer-ului, licenta, invitatia si drepturile
asociate contului. Node central furnizeaza organizatia, setarile, marcatorii si
configuratiile sincronizate. Exista si clienti de telemetrie, crash sender si
auto-update.

16. FISIERUL viewer.cpp

Fisierul viewer.cpp contine:

Grupele incluse:

- ferestre si transfer de fisiere.

Toate cele 52 de cereri de decompilare au returnat pseudocod valid. Nu au fost
inlocuite functii din cauza timeout-ului si nu au ramas raspunsuri MCP brute,
traceback-uri sau adrese invalide in fisier.

Limitari:
- binarul contine 53.338 functii, multe provenite din Qt, CRT, STL, QML,
  codecuri si template-uri;
- fisierul reuneste functionalitatile principale, nu fiecare functie;
- pseudocodul nu este sursa originala si nu este garantat compilabil;
- numele locale, tipurile incomplete, macro-urile si impartirea originala pe
  fisiere nu pot fi recuperate integral;
- identificatorii FUN_/DAT_/LAB_ sunt pastrati pentru trasabilitate.

17. CONCLUZIE

viewer.exe este consola desktop principala a sistemului. Ea se conecteaza la
noduri prin canale SSL si construieste o vedere unificata asupra organizatiei,
sesiunilor si monitoarelor. Modul Online reconstruieste cadre complete/delta in
timp real; History stocheaza si reda video/audio pe intervale; Control ofera
mouse, tastatura, clipboard si transfer de fisiere; Keylogger si Violations
incarca evenimente specializate; Charts si exporturile CSV/XLSX transforma
datele in rapoarte. Aplicatia foloseste Qt/QML si OpenGL pentru interfata si
randare si impune single-instance pentru profilul normal.
