7. TOP 5 CAUSES FOR STALE "RUNNING APPLICATIONS" METADATA
============================================================

Context-specific note:
- User reported video can look normal while Kickidler Viewer "Running Applications" remains stuck on an old process/tab.
- Therefore the likely bug is in focus/window metadata pipeline, not necessarily screen pixels.

1. WinEvent/hook/timer pipeline misses or drops a focus transition.
   - Relevant functions/APIs: SetWinEventHook, SetWindowsHookExA, FUN_140043c20, QTimer interval 500 ms.
   - Why: video can continue while last active HWND/PID/title metadata remains stale.
   - Confidence: High.

2. Internal QMap/QHash state is not updated or not flushed after a focus change.
   - Relevant functions: FUN_1400409b0, FUN_140043c20, vtable method at +0x68, FUN_140052240.
   - Why: stale "Running Applications" sounds like stale metadata cache.
   - Confidence: Medium-High.

3. Input desktop/session switch fails intermittently.
   - Relevant function: FUN_14003ebd0.
   - APIs: OpenInputDesktop, SetThreadDesktop, GetUserObjectInformationA.
   - Why: if tracking thread reads wrong desktop, GetForegroundWindow / GUI info may return old or unusable state.
   - Confidence: Medium.

4. IPC carries stale metadata even if local tracking updates correctly.
   - Relevant imports: QLocalSocket, QSharedMemory, named pipe APIs, events/mutexes.
   - Why: Running Applications can be a separate metadata channel from video.
   - Confidence: Medium.

5. Race/lock/wait in Qt timer or worker thread.
   - Relevant functions/imports: FUN_140043c20, QMutex, WaitForSingleObject, WaitForMultipleObjects, condition variables, QTimer.
   - Why: random occurrence across processes/tabs fits race/timing/lock issue better than an AutoCAD-only capture issue.
   - Confidence: Medium.

- WmiPrvSE.exe from OldKickExe is very likely the old Kickidler service/grabber component equivalent to the newer tlsservice.exe.
- It is not merely a subagent like old RuntimeBroker.exe.
- It imports and contains code paths for:
  - keyboard/mouse hooks
  - focus/window/session/desktop tracking
  - GDI capture
  - shared memory/local socket/named pipe IPC
  - Qt timer-driven metadata updates
  - user/session bridging through WTS

Relation to other executables:
- Direct readable strings linking to tlshost.exe/tssubservice.exe were not observed here.
- Functional relation is clear by role:
  - old RuntimeBroker.exe: subagent/UI/clipboard/settings/HTTP role.
  - old WmiPrvSE.exe: service/grabber/focus/input/capture role.
  - newer tlsservice.exe: same broad service/grabber role as this old WmiPrSE.exe.

Most relevant hypothesis for the user's issue:
- Since video can be normal while "Running Applications" is stale, the likely failure is not GDI frame capture itself.
- The likely failure is stale active-window metadata caused by missed focus event, failed desktop/session switch, stale QMap/QHash cache, or IPC flush/race in the metadata channel.
